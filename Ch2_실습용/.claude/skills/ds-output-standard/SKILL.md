# 팀 표준 결과물 (보고서 · 발표자료 · 대시보드)

팀원마다 AI 결과물의 형식과 품질이 달라지지 않도록, 아래 절차와 템플릿을 그대로 따른다.
디자인을 새로 만들지 않는다. **템플릿을 복사해 내용만 바꾸는 방식**이 원칙이다.

## 1. 유형 판별

| 요청 표현 | 유형 | 참고 문서 | 템플릿 |
|---|---|---|---|
| 보고서, 결과 보고, 기획안, 문서, 품의 | 보고서 (A4) | `references/doc.md` | `assets/doc-template.html` |
| 발표자료, 슬라이드, 장표, PT, 덱 | 발표자료 (1920×1080) | `references/slide.md` | `assets/slide-template.html` |
| 대시보드, 현황판, 모니터링, KPI | 대시보드 (웹 화면) | `references/dashboard.md` | `assets/dashboard-template.html` |

- "우리팀 스타일로 만들어줘"처럼 유형이 드러나지 않으면 사용자에게 세 가지 중 무엇인지 한 번만 묻는다.
- 공통 디자인 규칙은 모든 유형에서 `references/design-system.md`를 먼저 읽는다.

## 2. 작성 절차

1. **입력 확인**: 사용자가 준 자료(파일·수치·메모)를 읽는다. 보고 대상, 기준 시점, 작성 부서가 없으면 묻거나 `[확인 필요]`로 남긴다.
2. **참고 문서 읽기**: `references/design-system.md` + 해당 유형 문서.
3. **템플릿 복사**: 해당 템플릿을 결과 파일로 복사한 뒤 내용을 교체한다. 레이아웃 블록(카드, 표, 장표 유형)은 템플릿에 있는 것만 조합해 쓴다.
4. **내용 작성**: 유형별 문서의 구성 순서와 문장 규칙을 따른다.
5. **검증**: 아래 명령으로 검사하고, 오류(ERROR)는 모두 고친다. 경고(WARN)는 이유가 있으면 남겨 두고 응답에 그 이유를 적는다.
   ```
   node .claude/skills/ds-output-standard/scripts/check.js <결과파일.html> [doc|slide|dashboard]
   ```
6. **셀프 리뷰**: `references/design-system.md` 맨 아래 체크리스트를 확인하고, 결과 파일 경로와 `[확인 필요]` 항목을 사용자에게 보고한다.

## 3. 절대 규칙

- **수치·사실을 지어내지 않는다.** 입력 자료에 없는 값은 `[확인 필요]`로 표시한다. 템플릿의 예시 수치(4,812명, 1,240h 등)를 결과물에 남기지 않는다.
- **단일 standalone HTML**: 외부 리소스는 Google Fonts(`Gothic A1`, `Noto Sans KR`)만 허용. 차트 라이브러리·외부 이미지·CDN 스크립트 금지. 차트는 CSS/inline SVG로 그린다.
- **팔레트 밖 색상 금지**: `references/design-system.md`의 색상만 쓴다.
- 모든 숫자에는 단위와 기준 시점을 붙이고, 외부 수치에는 출처를 적는다.
- 문서·응답은 한국어로 작성한다.
- 결과 파일은 사용자가 지정한 위치에 저장한다. 지정이 없으면 프로젝트 루트에 `<주제>-report.html` / `<주제>-slides.html` / `<주제>-dashboard.html`로 저장한다.
