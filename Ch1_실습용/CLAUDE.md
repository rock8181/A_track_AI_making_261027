# 작업 규칙 (Ch1_실습용)

이 폴더의 작업 내용(매출 엑셀 분석, 반도체 뉴스 대시보드)을 바탕으로 정리한 규칙이다.

## 폴더 구성
- `sales.xlsx`: 2026-01~06 주문 120건 (Sales 시트, 컬럼: 주문번호/주문일자/지역/담당자/채널/제품/단가/수량/매출액)
- `sales_new.xlsx`: 2026-07~12 주문 120건, 같은 구조. 주문번호(ORD-0001~0120)가 `sales.xlsx`와 겹치지만 내용은 다름
- `semiconductor_news_dashboard.html`: 반도체 주간 뉴스 대시보드 (최종 산출물, 단일 파일)
- `image.png`: 대시보드 디자인 참고 이미지 (어두운 남색 배경, 시안·노랑 네온 관제 화면)

## 일반 원칙
- 응답과 문서는 한국어로 쓴다.
- 이 PC에는 Python이 없다. 엑셀은 PowerShell(zip/XML 파싱)이나 Node로 읽는다. Node는 사용 가능하다.
- 임시 파일과 중간 산출물은 스크래치패드에 두고, 이 폴더에는 최종 산출물만 둔다.
- 확인하지 못한 것은 확인했다고 쓰지 않는다. 브라우저로 못 본 화면은 "눈으로 확인 안 함"이라고 밝힌다.

## 엑셀 데이터 분석
- 분석 전에 컬럼 구조, 행 수, 기간, `단가 × 수량 = 매출액` 일치 여부, 주문번호 중복을 먼저 확인한다.
- 주문일자는 엑셀 일련번호다(46023 = 2026-01-01). 날짜로 변환해서 다룬다.
- 오늘 날짜 이후의 미래 날짜 행이 있으면 오류 가능성으로 따로 알린다 (`sales_new.xlsx`에 57건 있었음).
- 두 파일을 합칠 때는 주문번호가 겹친다는 점을 먼저 처리한다. 파일명 구분 컬럼을 추가하거나 번호 체계를 나눈다.
- 원본 xlsx는 요청 없이 수정하지 않는다. 수정이 필요하면 사본을 만든다.

## 뉴스 수집 (멀티 에이전트)
- 수집은 분야별 Haiku 서브에이전트가 병렬로 맡는다. 분야: 메모리, 파운드리, AI 반도체, 장비·정책, 시장·주가.
- 수집 기간은 최근 1주일이다. 기준일에서 7일 이내이고 날짜가 확인된 기사만 담는다. 날짜가 불명확하거나 범위 밖이면 제외하고, 건수를 채우려고 지어내지 않는다.
- 기사 한 건의 필드: `title, source, date(YYYY-MM-DD), url, summary(한국어 1~2문장), companies[], sentiment(positive|neutral|negative)`
- 분야별 결과는 `news_<분야>.json`으로 저장한다 (분야 키: `memory, foundry, ai, policy, market`). 0건이면 빈 배열 `[]`.
- 에이전트가 쓴 요약은 검증되지 않았다. 대시보드에 "수치는 원문 확인" 안내를 유지한다.
- 건수가 목표(6~10건)에 못 미치면 하단 "수집 한계" 박스에 분야별로 표시한다. 보강이 필요하면 매체를 지정해 재수집한다.

## 대시보드(HTML) 개발
- 결과물은 외부 라이브러리·CDN 없는 단일 HTML 파일이다. 데이터는 `const DATA = __DATA__;`로 주입한다.
- 구조는 `shell`(골격·CSS·상태·필터·기사 목록·헬퍼), `panel_*.js`(차트 패널 6개), `build2.js`(조립)로 나눈다. 패널은 `PANELS.<id> = function(items, ctx){ return html; }` 형식만 쓴다.
- 패널 6개: `kpi, cat, sent, day, co, catpie`. 패널 하나가 실패해도 그 패널만 "로드 실패"로 표시하고 나머지는 동작해야 한다. 데이터가 비어도 오류가 없어야 한다.
- 범위 토글은 `전체 / 글로벌 뉴스 / 삼성전자` 3개다. 기업 목록에 `삼성전자`가 있거나 제목·요약에 `삼성`이 있으면 삼성전자, 아니면 글로벌 뉴스다. 토글은 KPI·차트·기사 목록에 함께 적용한다.
- 디자인은 다크 고정이다. 시안 `#19e3ff`와 노랑 `#ffd426` 네온, 얇은 시안 테두리 패널, 사다리꼴 헤더, 900px 미만에서 1단 레이아웃.
- 보안: 데이터는 전부 `esc()`로 이스케이프하고, 링크는 http/https만 허용하며 `target="_blank" rel="noopener noreferrer"`를 붙인다. 데이터 JSON을 주입할 때 `<`는 `<`로 바꾼다.
- 빌드 후 `<script>` 내용을 `new Function`으로 문법 검사한다. 가능하면 브라우저로 화면까지 확인한다.

## 서브에이전트 운영
- 하위 작업은 Haiku, 총괄(골격·통합·검증)은 Opus가 맡는다.
- 여러 에이전트가 같은 파일을 동시에 고치지 않게 파일 단위로 담당을 나눈다. 모듈 계약서(`CONTRACT.md`)를 먼저 쓰고 프롬프트에서 참조한다.
- 프롬프트에는 절대 경로를 정확히 쓴다. 경로가 깨지거나 "같은 폴더" 같은 모호한 표현을 쓰면 파일이 엉뚱한 곳에 생긴다 (실제로 `panel_day.js`가 이 폴더에 생겼다).
- 에이전트의 완료 보고는 "에이전트가 한 말"로 취급한다. 파일 존재, 빌드 결과, 건수는 직접 확인한 뒤 보고한다.
- 작업이 겹치게 된 에이전트는 중단하고 다시 나눈다.

## 브라우저 확인
- 크롬 확장은 `file://`과 `localhost` 접속이 막힐 수 있다. 두세 번 시도해서 안 되면 반복하지 말고 사용자에게 직접 열어 보라고 요청한다.
- 임시 로컬 서버를 띄웠다면 종료 여부를 확인하고, 열었던 탭은 닫는다.
