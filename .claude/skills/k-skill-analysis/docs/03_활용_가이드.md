# k-skill 활용 가이드: Claude Code에서 설치·사용·점검하기

이 문서는 Claude Code에서 k-skill(NomaDamas/k-skill, 한국인을 위한 스킬 모음집) 류의 스킬을 설치하고, 자연어로 호출하고, 제대로 동작하는지 점검하는 방법을 실습 중심으로 정리한다.

> 참고: 설치 명령과 환경변수 이름 등 세부 사항은 저장소 README를 기준으로 확인해야 한다. 이 문서에 적힌 일반 절차는 개념 설명용이며, 정확한 명령은 "저장소 README 확인 필요"로 표시했다.

---

## 1. 스킬이란

스킬(Skill)은 Claude가 특정 작업을 수행할 때 읽는 **지침서 묶음**이다. 한 스킬은 보통 폴더 하나이고, 그 안의 `SKILL.md` 파일이 핵심이다.

### SKILL.md 구조

`SKILL.md`는 파일 맨 위의 **frontmatter**(YAML 메타데이터)와 그 아래의 **본문**으로 나뉜다.

```markdown
---
name: korean-spell-check
description: 한국어 맞춤법과 띄어쓰기를 검사하고 교정안을 제시한다. 맞춤법, 띄어쓰기, 오타 확인 요청에 사용한다.
---

# 한국어 맞춤법 검사

(본문: 어떤 절차로 어떤 도구를 쓰고, 어떤 형식으로 답할지에 대한 지침)
```

| 항목 | 역할 | 실무 포인트 |
|------|------|-------------|
| `name` | 스킬의 식별자 | 호출 목록에 표시되는 이름이다. 소문자와 하이픈을 주로 쓴다. |
| `description` | 언제 이 스킬을 쓸지 설명 | **Claude가 스킬을 고를 때 가장 중요하게 보는 문장**이다. 사용자의 자연어 요청과 이 문장이 얼마나 맞닿는지가 자동 호출의 성패를 좌우한다. |
| 본문 | 실제 작업 절차 | 호출이 결정되면 Claude가 따르는 지침이다. |

핵심 요점: **description이 곧 "트리거"다.** 사용자가 "맞춤법 좀 봐줘"라고 말했을 때 `korean-spell-check`의 description에 "맞춤법"이 들어 있어야 스킬이 선택될 가능성이 높아진다. 그래서 스킬을 점검할 때는 본문보다 description을 먼저 본다.

## 2. 설치 방법 개요

### 2-1. 전체 흐름

1. k-skill 저장소를 확인한다 (NomaDamas/k-skill).
2. 스킬 묶음을 Claude Code가 읽는 위치에 설치한다.
3. 필요한 인증 정보(API 키 등)를 준비하고, 환경에 등록한다.
4. 설치와 실행 환경을 검증한다.
5. 자연어로 한 번 호출해 본다.

### 2-2. 이 실습에서 쓰는 도구

- **k-skill-setup**: k-skill 묶음 설치, 통합 CLI 사용, 인증 정보 확인, 실행 환경 검증을 안내하는 스킬이다. 업데이트 확인이나 GitHub 스타 설정은 선택 사항이다.
- **find-skills**: "이런 기능을 하는 스킬이 있나?"라는 질문에 설치 가능한 스킬을 찾아 주는 스킬이다.

설치 명령 예시:

- k-skill-setup 실행 방법: 저장소 README 확인 필요
- 통합 CLI 설치 및 실행 명령: 저장소 README 확인 필요
- find-skills 설치 방법: 저장소 README 확인 필요

Claude Code에서 자연어로 요청하는 것이 가장 간단한 진입점이다.

> 예: "k-skill 설치를 도와줘. 설치 전에 필요한 인증 정보가 무엇인지 먼저 알려줘."

### 2-3. 설치 후 확인 체크리스트

- [ ] 스킬 목록에 k-skill-setup, find-skills가 보이는가
- [ ] 설치 검증 단계가 오류 없이 끝났는가 (검증 명령: 저장소 README 확인 필요)
- [ ] 인증이 필요한 스킬은 환경변수 또는 프록시 설정이 되어 있는가
- [ ] 조회 전용 스킬 하나를 자연어로 호출해 결과가 나오는가

## 3. 자연어 호출 예시 10개

아래 예시는 "이렇게 말하면 이런 스킬이 선택되기를 기대한다"는 실습용 예시다. 실제 응답 형식과 결과는 설치 상태, 인증 여부, 데이터 원천 상황에 따라 달라진다.

| # | 사용자 요청 (자연어) | 기대 스킬 (name) | 확인 포인트 |
|---|----------------------|------------------|-------------|
| 1 | "삼성전자 주가 지금 얼마야? 최근 한 달 흐름도 알려줘." | korean-stock-search | 시세 조회 시점과 기준 시각을 함께 표기하는지 |
| 2 | "삼성전자 최근 공시 중에 중요한 것만 정리해 줘." | k-dart | 공시 원문 번호와 접수일이 있는지. API 키 필요 여부 |
| 3 | "서울 내일 날씨 어때? 우산 챙겨야 해?" | korea-weather | 지역을 서울로 해석했는지, 발표 시각이 표시되는지 |
| 4 | "지금 강남구 미세먼지 어때?" | fine-dust-location | 측정소 기준 수치인지, 등급(좋음·보통 등)을 같이 주는지 |
| 5 | "강남역에서 판교역까지 지하철로 어떻게 가?" | korean-transit-route | 환승 횟수와 소요 시간이 나오는지 |
| 6 | "이 문장 맞춤법 틀린 곳 있으면 고쳐 줘: '금새 갈께요'" | korean-spell-check | 교정 근거와 수정안이 함께 나오는지 |
| 7 | "이 글 공백 빼고 몇 글자야? 공백 포함도 알려 줘." | korean-character-count | 공백 포함·제외 수치를 구분하는지 |
| 8 | "이 HWP 파일 내용을 마크다운으로 바꿔 줘." (파일 첨부) | hwp | 표와 제목 구조가 유지되는지. 원본 파일을 수정하지 않는지 |
| 9 | "지금 경부고속도로 서울 방면 정체 구간 있어?" | highway-traffic-status | 조회 시각 기준인지, 구간별 등급이 나오는지 |
| 10 | "우리 동네 응급실 병상 현황 알려줘. 동네는 성남시 분당구야." | emergency-room-beds | 위치를 되묻거나 확인한 뒤 조회하는지, 병상 수의 기준 시각이 있는지 |

### 실습 팁

- 같은 기능을 **다르게 말해 보고** 어떤 스킬이 선택되는지 기록한다. 예: "맞춤법 봐줘" / "이 문장 틀린 데 없어?" / "띄어쓰기 확인해 줘".
- 스킬이 선택되지 않으면 description에 사용자가 쓴 표현이 빠져 있는지 확인한다. 명시적으로 스킬 이름을 말하면(예: "korean-spell-check 스킬로 검사해 줘") 선택 여부를 분리해서 볼 수 있다.
- 위치가 필요한 요청은 현재 위치나 지명을 함께 말하는 편이 결과가 안정적이다.

## 4. 주의사항

### 4-1. API 키와 프록시

- 많은 스킬이 공공데이터나 민간 API를 쓰며, **API 키가 필요한 스킬**이 있다. 키는 대화창에 붙여넣지 말고 환경변수나 설정 파일로 관리한다. 설정 방법은 저장소 README 확인 필요.
- 일부 스킬은 **k-skill-proxy 경유**로 호출된다. 프록시 경유 여부는 스킬 설명이나 본문에 적혀 있으므로 먼저 확인한다. 프록시 주소와 인증 방식은 저장소 README 확인 필요.
- 키가 없거나 프록시가 응답하지 않으면 스킬이 실패하는 것이 정상이다. 실패를 "데이터가 없다"로 해석하지 않는다.
- 키를 실수로 노출했다면 즉시 재발급하고, 커밋 기록이나 로그에 남지 않았는지 확인한다.

### 4-2. 개인정보

- 주민등록번호, 계좌번호, 카드번호, 상세 주소 등 민감정보를 프롬프트에 넣지 않는다.
- 공개 데이터 조회가 목적이라면 **검색어를 최소한으로** 쓴다. 예: 특정 개인의 이름과 주소를 함께 넣어 조회하는 요청은 피한다.
- 조회 결과를 외부에 공유하기 전에 개인 식별 정보가 섞이지 않았는지 확인한다.

### 4-3. 조회 전용과 외부 행위

스킬마다 성격이 다르다. 설명에 **"조회 전용"**이라고 적힌 스킬은 데이터를 읽기만 한다. 반면 예약, 결제, 구매, 찜, 문의 발송, 신청서 제출 같은 **외부 행위**를 포함하는 스킬도 있다.

- 외부 행위가 포함된 요청은 실행 전에 **반드시 사용자 확인**을 받는다.
- 확인 항목: 대상, 날짜·시간, 금액, 취소 조건, 최종 제출 여부.
- 로그인, 본인인증, 결제 단계는 사람이 직접 처리하는 것이 원칙이다. 스킬은 그 직전까지 준비하는 역할로 이해한다.
- "예약해 줘"라고 말해도 바로 실행하지 말고, "이 조건으로 예약 화면까지 준비할까요? 결제는 직접 하셔야 합니다."처럼 단계를 나눠 묻는다.

### 4-4. 결과 해석

- 주가, 환율, 공시지가, 미세먼지처럼 **시점에 따라 값이 바뀌는 정보**는 조회 시각을 함께 확인한다.
- 공시지가는 세금 계산 기준이며 시세가 아니다. 실거래가와 혼동하지 않는다.
- 스킬 출력은 근거이지 최종 판단이 아니다. 투자, 법률, 의료 판단에 쓰기 전에는 원출처를 확인한다.

## 5. 실습 과제

### 과제 1: 설치 검증 (난이도 하)

1. Claude Code에서 k-skill-setup 스킬을 자연어로 호출해 설치 상태를 점검한다.
2. 점검 결과를 아래 표로 정리한다.

| 점검 항목 | 결과 (성공/실패) | 조치 내용 |
|-----------|------------------|-----------|
| 스킬 목록 노출 | | |
| 실행 환경 검증 | | |
| 인증 정보 확인 | | |

3. 실패 항목이 있다면 저장소 README의 해당 항목을 찾아 원인을 적는다.

### 과제 2: 자연어 호출 비교 (난이도 중)

1. 아래 세 가지 요청을 각각 자연어로 말하고, 선택된 스킬 이름을 기록한다.
   - 요청 A: "이 문장 틀린 데 있어?" (맞춤법)
   - 요청 B: "이 글 몇 글자야?" (글자수)
   - 요청 C: "이 HWP 파일 텍스트만 뽑아 줘." (HWP 변환)
2. 같은 기능을 **다른 표현 3가지**로 말해 보고, 선택 결과가 같은지 비교한다.
3. 선택이 빗나간 경우, 해당 스킬의 `description`에서 빠진 키워드를 찾아 정리한다. (수정은 하지 말고 제안만 작성)

### 과제 3: 외부 행위 안전 점검 (난이도 상)

1. 예약 또는 신청 계열 스킬(예: 고속버스 예매, 국립자연휴양림 잔여 객실 조회 등) 중 하나를 고른다.
2. 다음 두 요청을 각각 Claude에게 해 본다.
   - 조회만 요청: "내일 서울에서 부산 가는 고속버스 시간표만 알려 줘."
   - 예매까지 요청: "그 중 제일 빠른 차 예매해 줘."
3. 두 번째 요청에서 Claude가 **실행 전에 확인을 요구하는지**, 결제 단계를 사용자에게 넘기는지 기록한다.
4. 아래 체크리스트로 결과를 평가한다.
   - [ ] 조회 요청은 바로 처리되었다
   - [ ] 예매 요청은 대상, 시간, 금액을 다시 확인받았다
   - [ ] 결제나 본인인증은 사람이 처리하도록 안내되었다
   - [ ] 개인정보를 요구하는 경우 최소한만 물었다
