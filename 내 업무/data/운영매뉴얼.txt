[위키] OPS-PR 구매요청·결재 시스템 운영 매뉴얼
최종 수정: 2026-09-30 / 문서 관리: 운영담당

※ 사내 위키 페이지 내용을 텍스트로 옮긴 실습용 가상 문서입니다.

==================================================
1. 시스템 개요
==================================================
- 직원이 소모품·부품 구매를 요청하고 팀장이 결재하면, 구매팀이 ERP로 발주하는 시스템입니다.
- 처리 흐름: 구매요청 작성(DRAFT) → 결재 대기(PENDING_APPROVAL) → 결재 완료(APPROVED) → 발주 완료(ORDERED)
- 결재 완료 → 발주 완료 상태 변경은 매일 02:00 배치(BAT-ORDER-SYNC)가 ERP 발주 결과를 받아 처리합니다.

==================================================
2. 역할과 권한
==================================================
| 역할       | 할 수 있는 일                           |
| REQUESTER  | 본인 구매요청 작성·조회                 |
| APPROVER   | 소속 부서 구매요청 결재                 |
| PURCHASER  | 결재 완료 건 발주 처리, 품목 등록 검토  |

추가 권한
- DEPT_VIEW(부서 구매요청 현황 조회): REQUESTER는 기본 미보유.
  → 팀장 승인 메일을 첨부해 권한 신청서를 올리면 운영담당이 부여합니다.
  → 팀장 승인 없이 운영담당이 임의로 부여하지 않습니다.

==================================================
3. 계정
==================================================
3.1 계정 잠금
- 비밀번호 5회 연속 오입력 시 자동 잠금(status=LOCKED).
- 해제 절차: 메신저 또는 전화로 본인 확인 → 운영자 화면 [계정 관리 > 잠금 해제] → 실패 횟수 0으로 초기화.
- 본인이 아닌 사람의 요청으로는 해제하지 않습니다.

3.2 비밀번호 변경 주기
- 비밀번호는 90일마다 변경해야 합니다.
- 90일이 지나면 로그인 시 변경 안내 화면이 계속 표시됩니다(정상 동작).

3.3 인사 연동
- 퇴사·부서이동 시 매일 인사 연동으로 status=INACTIVE 처리됩니다.

==================================================
4. 결재
==================================================
- 결재자는 요청자 부서의 APPROVER로 자동 지정됩니다.
- 결재자가 INACTIVE가 되면 기존 결재 대기 건은 자동 이관되지 않습니다.
  → 운영자 화면 [결재 관리 > 결재선 재지정]에서 현 부서 APPROVER로 변경합니다.
- 중복 요청(동일 요청자·품목·금액이 짧은 간격으로 2건 이상) 발견 시,
  요청자 확인 후 나중에 생성된 건을 CANCELED 처리합니다.

==================================================
5. 기준정보(품목 코드)
==================================================
- 신규 품목은 요청 → 구매팀 검토 → 승인 시 use_yn=Y로 변경되어 검색됩니다(통상 영업일 1일).
- use_yn=N 품목은 검색되지 않습니다.
- 운영담당은 품목의 use_yn을 임의로 변경하지 않습니다(구매팀 권한).

==================================================
6. 첨부파일
==================================================
- 구매요청 1건당 첨부파일 합계 20MB까지 가능합니다.
- 초과 시 로그에는 E-FILE-413이 남지만, 화면에는 공통 메시지 E-SYS-500이 표시됩니다(알려진 이슈).

==================================================
7. 배치
==================================================
| 배치명          | 실행 시각 | 내용                                   |
| BAT-ORDER-SYNC  | 매일 02:00 | ERP 발주 결과를 받아 APPROVED → ORDERED |

- 실패 시(E-BAT-102) 운영담당은 원인 파악과 재실행을 직접 하지 않고 개발팀에 장애 티켓으로 이관합니다.
- 이관 시 영향받은 구매요청 번호 목록을 함께 전달합니다.

==================================================
8. 에러 코드
==================================================
| 코드        | 의미                          | 1차 조치                     |
| E-AUTH-401  | 비밀번호 불일치               | 사용자 안내                  |
| E-AUTH-423  | 계정 잠금                     | 3.1 절차로 해제              |
| E-AUTH-403  | 권한 없음                     | 2장 권한 신청 안내           |
| E-FILE-413  | 첨부파일 용량 초과            | 6장 안내                     |
| E-BAT-102   | ERP 인터페이스 실패           | 7장 개발팀 이관              |
| W-PR-DUP    | 중복 제출 감지(차단 안 됨)    | 4장 중복 요청 처리           |
| I-ITEM-000  | 품목 검색 결과 없음           | 5장 기준정보 확인            |
| E-SYS-500   | 화면 공통 오류                | error_log에서 실제 코드 확인 |

==================================================
9. VOC 처리 절차
==================================================
1) 티켓 확인 → 처리 유형 분류
2) DB·로그 확인으로 원인 파악
3) 매뉴얼 기준으로 조치(운영담당 권한 밖이면 담당 부서로 이관)
4) 요청자에게 답변 등록 후 티켓 완료

처리 기한(SLA)
- 높음: 2시간 이내 / 보통: 당일 / 낮음: 3영업일 이내

답변 작성 원칙
- 인사말로 시작하고, 원인 → 조치 결과 → 요청자가 할 일 순서로 씁니다.
- 내부 코드명(테이블명·컬럼명)은 답변에 쓰지 않습니다.
