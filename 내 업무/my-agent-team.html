AI 2		 전체 티켓을 한 번에 보고 처리 유형·우선순위 재분류, 중복 VOC 식별 route (장애·문의 / 중복 VOC / 개선 요청) = Router 조건

voc-analyst
AI 4		 장애·문의 티켓 1건의 로그·DB를 매뉴얼·이력·노하우와 대조해 원인과 조치 판단 근거 · 원인 · 조치
직접 조치 / 이관 / 안내 · 선행 조건
→ analysis/<티켓>.json		 로그의 실제 에러 코드 우선 · 운영담당 권한 밖 일은 직접 조치로 넣지 않음 · 답변은 안 씀
voc-answer-writer
AI 5		 경로별 답변 초안 작성 (원인·조치 답변 / 병합 안내 / 이관 안내), FAIL이면 지적사항 반영해 재작성 답변 + revision
→ answer/<티켓>.json		 실행 전 조치를 끝난 것처럼 쓰지 않음 · 지적받지 않은 부분은 그대로
voc-answer-reviewer
AI 5-1		 답변 1건을 4가지 기준(근거·구성·표현·이관)으로 검토 PASS / FAIL + 문제점
→ review/<티켓>.json		 답변을 직접 고치지 않음 · 기준에 없는 취향으로 FAIL 주지 않음

적용한 패턴

패턴적용 위치내용
Parallel ③AI 4 → AI 5 (티켓별)티켓마다 조회 자료는 다르지만 처리 기준은 같아 동시에 실행. AI 2는 중복 식별을 위해 전체를 한 번에 처리
Router코드 3 다음 (티켓 입구)장애·문의 → AI 4 → AI 5 / 중복 VOC → AI 5 병합 안내 / 개선 요청 → AI 5 이관 안내
Gen / EvalAI 5 ⇄ AI 5-1FAIL이면 같은 티켓의 AI 5가 재작성 (최대 2회). 그래도 FAIL이면 "검토 미통과"로 보고서에 표시

답변 검토 기준 (AI 5-1)

기준확인할 것
1. 근거AI 4(병합·이관 건은 AI 2) 판단과 일치하고 근거 없는 약속·일정·원인이 없음
2. 구성인사말 → 첫 문장에 결론 → 원인 → 조치 결과 → 요청자가 할 일
3. 표현내부 코드명(테이블·컬럼명·상태 코드값) 없음, 요청자를 탓하는 표현 없음
4. 이관이관 건이면 어디로 넘겼고 언제쯤 연락이 갈지 포함

모두 충족 → PASS · 하나라도 미충족 → FAIL
