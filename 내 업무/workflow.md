# Workflow: 운영 시스템 VOC 처리

## 1. 전체 Task 실행 순서

| 순서 | Task | 실행 주체 | 비고 |
|---|---|---|---|
| 1 | VOC 티켓 불러오기 및 요청자 정보(부서·역할·계정 상태) 조회 | 코드 | |
| 2 | 문의 내용 분석 및 처리 유형·우선순위 재분류 | AI | 전체 티켓을 한 번에 처리 (중복 VOC 식별), 판단 결과가 Router 조건 |
| 3 | 관련 시스템 로그·DB 조회 (에러 로그, 처리 이력, 기준정보) | 코드 | |
| 4 | 원인 분석 및 조치·이관 방안 판단 (매뉴얼·과거 처리 이력·노하우 대조) | AI | Parallel ③ (티켓별), Router: 장애·문의 유형만 실행 |
| 5 | 답변 초안 작성 | AI | Parallel ③ (티켓별), Router에 따라 답변 종류가 다름, Gen / Eval의 Generator |
| 5-1 | 답변 검토 | AI | Gen / Eval의 Evaluator (티켓별) |
| 6 | VOC 처리 검토 보고서 생성 (요약 집계·티켓별 카드 배치) | 코드 | |
| 7 | 보고서 검토 및 답변 확정 | 사람 | |

## 2. Parallel 구조

- 대상 AI Task: 4 원인 분석·조치 판단 → 5 답변 초안 작성
- 유형: ③ 다른 입력 × 같은 에이전트
- 병렬 작업: 티켓별 "4 → 5"를 티켓마다 동시에 실행
- 이유: 티켓마다 조회 자료는 다르지만 처리 기준(매뉴얼·이력·노하우)은 같고, 티켓끼리 서로의 결과를 기다릴 필요가 없음
- 제외: Task 2는 중복 VOC 식별을 위해 전체 티켓을 함께 처리. 티켓 안에서 4 → 5는 순차 실행

## 3. Router 구조

- 위치: 티켓별 Parallel 구간 입구 (코드 3 다음)
- 분기 조건: AI 2의 처리 유형 판단 결과

| AI 2 판단 결과 | 다음 실행 |
|---|---|
| 장애·문의 (계정, 권한, 결재, 기준정보, 오류, 배치 등) | AI 4 원인·조치 판단 → AI 5 답변 초안 |
| 중복 VOC | AI 5 답변 초안 (대표 티켓 병합 안내) |
| 개선 요청 | AI 5 답변 초안 (개선요청 게시판 이관 안내) |

- 이유: 중복 VOC와 개선 요청은 원인 분석 없이 병합·이관만 하는 유형이라 AI 4를 거칠 필요가 없음

## 4. Gen / Eval 구조

- 대상 AI Task: 5 답변 초안 작성 (세 경로 모두)
- Generator: AI 5. 답변을 작성하고, FAIL이면 지적받은 부분을 수정
- Evaluator: 5-1 답변 검토 AI. 답변을 직접 수정하지 않고 PASS / FAIL과 문제점만 전달
- 검토 기준 (운영 매뉴얼 답변 작성 원칙 + 처리 노하우 문서)
  1. 근거: 답변 내용이 AI 4의 원인·조치 판단(병합·이관 건은 AI 2 판단)과 일치하고 근거 없는 내용이 없음
  2. 구성: 인사말로 시작, 원인 → 조치 결과 → 요청자가 할 일 순서, 첫 문장에 결론
  3. 표현: 내부 코드명(테이블·컬럼명) 없음, 요청자를 탓하는 표현 없음
  4. 이관 건: 어디로 넘겼고 언제쯤 연락이 갈지 포함
- PASS / FAIL 조건: 모든 기준 충족 → PASS, 하나 이상 미충족 → FAIL
- FAIL 시 돌아갈 Task: 같은 티켓의 AI 5 (문제점을 전달받아 재작성)
- 최대 반복 횟수: 재작성 2회 (초안 + 수정 2회, 검토 최대 3회)
- 최대 횟수 도달 후에도 FAIL: 멈추지 않고 "검토 미통과"로 표시해 코드 6 보고서에 지적사항과 함께 싣고 사람 7이 확인

## 5. Task 간 연결 관계

- 입력 자료 → 1
- 1 → 2 (티켓 + 요청자 정보)
- 2 → 3 (유형·우선순위·중복 그룹)
- 3 → 티켓별 Parallel 분기 → Router (AI 2 판단 결과)
  - 장애·문의: 3 → 4 → 5
  - 중복 VOC: 3 → 5 (병합 안내)
  - 개선 요청: 3 → 5 (이관 안내)
- 5 → 5-1 (답변 검토)
  - PASS: 5-1 → 6
  - FAIL: 5-1 → 5 (재작성, 최대 2회) → 5-1
  - 최대 횟수 도달 후 FAIL: "검토 미통과" 표시 → 6
- 5-1 → 6 (모든 티켓 결과 취합)
- 6 → 7 (VOC 처리 검토 보고서)

## 6. 전체 Workflow 시각화

```
[입력: VOC 티켓 · 시스템 DB · 매뉴얼 · 과거 이력 · 노하우]
          ↓
[코드 1: 티켓 불러오기 + 요청자 정보 조회]
          ↓
[AI 2: 문의 분석 + 유형·우선순위 재분류]   ← 전체 티켓을 한 번에 (중복 VOC 식별)
          ↓
[코드 3: 관련 로그·DB 조회]
          ↓
   ┌──────────────┼──────────────┐
   ↓              ↓              ↓
[티켓 A]       [티켓 B]   ...  [티켓 N]       ← Parallel ③ (티켓마다 아래 Router 적용)

   ── 티켓 1건 내부 ────────────────────────
              [AI 2 판단 결과]                 ← Router
       ┌──────────┼──────────┐
   장애·문의     중복 VOC     개선 요청
       ↓           │           │
 [AI 4 원인·조치]   │           │
       ↓           ↓           ↓
 [AI 5 답변 초안 / 병합 안내 / 이관 안내] ←──────┐   ← Generator
                   ↓                          │
        [AI 5-1 답변 검토 (Evaluator)]          │
                   ↓                          │
            ┌──────┴──────┐                   │
          PASS          FAIL ─────────────────┘   (문제점 전달, 재작성 최대 2회)
            ↓             ↓ 최대 횟수 도달
     티켓 결과 완료    "검토 미통과" 표시 후 완료
   ──────────────────────────────────────

   └──────────────┼──────────────┘
          ↓
[코드 6: 검토 보고서 생성]   ← 검토 미통과 건은 지적사항 함께 표시
          ↓
[사람 7: 보고서 검토 + 답변 확정]
```
